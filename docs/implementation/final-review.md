### P2：新建 Page/Task/Project 草稿尚未统一接入未保存保护

主要位置：`web/src/features/page/Pages.tsx:83`；同类位置：`web/src/app/App.tsx:413`、`web/src/features/project/ProjectForm.tsx`。

新建 Page 的标题/父级仅保存在 Pages 本地 state（28–29 行），创建表单没有 data-dirty，也没有 beforeunload。应用路由阻止器只检测 `[data-dirty="true"]`（App.tsx:35–36），现有 PageEditor 的 data-dirty 只覆盖已存在对象的编辑。

确定的丢失路径：进入项目页面列表，在“新页面标题”输入草稿但不创建，切换任务或今日工作台。Pages 卸载，标题与父级无提示丢失；刷新同样无保护。Task 新建标题/父级与 Project 新建或修改表单也没有关闭标签页/刷新保护。阶段 3 对新建 Event 已作相同保护，其他创建入口未覆盖。

建议：为这些创建/项目表单统一判断 dirty，并接入路由离开及 beforeunload；取消/成功提交后解除保护，提交失败继续保留。至少覆盖新建 Page 输入后跳转被取消、刷新有提示，以及成功创建跳转不误报。创建请求在途也应纳入保护。

依据：技术设计第 5 节明确“路由离开和关闭标签页时检查未保存状态”；产品设计要求页面离开提示未保存内容。此发现由当前组件生命周期与阻止条件核对，未重复运行已有检查。

- Project 表单以初始快照比较 dirty，busy 也受保护；取消有显式丢弃确认，失败保留草稿，成功提交关闭表单后导航。
