- 共享选择器以同项目未删除对象为候选，提供 Page 完整路径、Task 阶段和 Event 部署时区时间；对象更新后刷新关系信息。

### P2：仅修改描述也会静默改变 Event 时间

位置：`web/src/features/event/time.ts:3`、`web/src/features/event/Events.tsx:272`（保存转换在 284–285 行）。

`toInput` 将合法服务端时间截断到分钟，丢失秒、毫秒和原始偏移；编辑器每次保存正文或标题时也无条件转换并发送起止时间。已用当前 luxon 运行最小转换验证：`2026-10-24T09:00:30+08:00` 经输入值 `2026-10-24T09:00` 回写为 `2026-10-24T09:00:00.000+08:00`。因此 API 创建的合法时间会在编辑正文时被改变；少于一分钟的合法日程甚至可能被回写为相同起止而保存失败。部署使用 DST 时区时，无偏移墙钟值还无法保留回拨重复小时中的原始瞬间。

建议：保留原始 RFC3339 值，仅在用户确实修改对应时间字段时重新转换；时间输入需要明确精度及重复小时偏移处理。补充“秒级起止仅改正文保持原瞬间”的回归验证。

### P2：新建 Event 草稿绕过离开保护

位置：`web/src/features/event/Events.tsx:145`。

新建表单的标题和起止时间保存在 `Events` 的本地 state，但表单没有 `data-dirty`，也未注册 `beforeunload`。应用路由保护只检查 `[data-dirty="true"]`（`web/src/app/App.tsx:33`）。选择时间并输入新日程标题后，切换任务/笔记/其他项目可直接卸载表单，浏览器刷新也没有提示，输入无提示丢失。已有 Event 详情编辑器的保护不覆盖这个创建表单。

建议：创建表单纳入同一离开与关闭保护，创建成功后清除 dirty；覆盖路由跳转和刷新时保留/确认丢弃创建草稿的行为。

## 修复复核（1c9d5b7）

本轮限定复核上述两项及修复直接引入的问题，依据当前实现与 `/tmp/noteapp-stage3-final-review.diff`。沿用协调者已实际完成的 19 个前端单测、Brave 5/5 浏览器检查（包含 LA/London 保秒与离开保护），未重复运行。

- **时间保真问题已解决。** EventEditor 对未变化的时间输入保留原始 RFC3339 值，包括秒及原偏移；用户改动时间字段才调用 fromInput。fromInput 明确拒绝 DST 跳时与回拨歧义时间。已有回归用例覆盖正文修改保秒，以及回拨小时原偏移保留。
- **创建草稿离开保护已解决。** 新建表单标记 `data-dirty="true"`，接入应用现有路由确认；selection 存在时注册 beforeunload，取消或创建成功清除 selection 后注销。失败保留表单。
- 未发现上述修复引入的新增重要问题。
