# 后端对象契约与明确的属性区域

## 修正
上一轮共用容器不足以表达清晰的属性区，也缺少后端对象和属性定义。本轮增加标题为“属性”的统一分组，三类对象都在这里展示固有属性和折叠关联。

- 任务：阶段、优先级、截止日期、父任务、关联。
- 笔记：父笔记、顺序、关联；原移动操作仍执行专用move校验。
- 日程：开始时间、结束时间、关联；保持部署时区显示与输入。

## 后端
- internal/object 定义 Type、Entity、Object、Definition、PropertyDefinition。具体任务、笔记和日程实现 AsObject，声明各自固有属性。
- GET /api/v1/object-types/{type} 返回固定属性定义，包括键、名称、值类型、默认值和修改方式。前端直接使用此定义安排属性区，避免三套独立展示规则。
- GET /api/v1/objects/{type}/{id} 返回统一对象视图，包含真实属性值、双向关联和归档只读状态。
- 写操作继续复用已验证的专用事务接口，避免复制业务约束。数据库、已有接口、对象ID和数据兼容，无迁移，不增加自定义字段或EAV存储。
