# 项目菜单与删除确认统一（2026-10-25）

沿用已确定的 Plane 风格：黑白、细灰线、紧凑字号，深蓝用于焦点和导航，红色只表达危险操作。

根因：删除预览嵌在项目Popover里；旧CSS在出现dialog时把整个菜单移动到中央并扩宽，内联确认仍沿用暖色边框，使导航菜单和确认混在同一表面。

改动：项目菜单固定紧凑宽度、统一16px线性图标、行高、分组和焦点。删除时关闭菜单，把共用DeleteButton的确认内容通过portal放到原生模态dialog，复用白底、灰线和相同字体。对象预览有高度限制，长标题省略，取消优先获得焦点，Escape取消并回到入口；请求处理中禁止关闭。确认仍调用原预览快照、版本冲突重新预览、删除批次和恢复API，不改后端或数据库。

选择独立确认而非在菜单中展开，是为让危险操作获得清晰的层级和受保护焦点，避免菜单随内容膨胀。清除已不适用的红框/绝对定位/:has(dialog)规则，新增限定范围的menus.css，未重设整个应用主题。

验证：66/66前端单测；最终Docker多阶段构建（含TypeScript检查）通过，保留既有大chunk提示。9/9相关浏览器回归通过，覆盖1280/390宽度、长名称、模态焦点、Escape取消/焦点恢复、请求处理中禁止关闭、预览刷新失败时保留可见错误并禁用旧确认，以及原有删除恢复/409重新预览/归档/保存冲突。后端代码和schema未变，本次未重复Go测试。
