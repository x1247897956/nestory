## 重要缺陷

### [P2] 项目编辑草稿没有固定基准版本，可覆盖其他标签页修改

位置：web/src/app/App.tsx:448–455；web/src/features/project/ProjectForm.tsx:12–13。

复现：A 标签页打开修改项目弹窗（版本 1）并输入草稿；B 标签页修改相同项目并保存成版本 2；切回 A，等待 TanStack Query 默认的窗口聚焦刷新取得版本 2，再提交 A 的弹窗。弹窗 title/description 仍来自版本 1 的 useState，但提交闭包读取最新 p.version=2，因此服务器接受请求并覆盖 B 的内容，而非返回 409。

影响：项目修改的乐观锁对用户编辑基准失效，违反两个标签页先后修改同一版本时后提交收到冲突的要求。

建议：打开弹窗时固定项目 ID、version 和初始字段；提交该草稿时使用固定 version。收到冲突保留弹窗草稿，并提供明确的重新载入流程。

### [P2] 后台查询失败会卸载任务编辑器，静默丢失未保存草稿

位置：web/src/app/App.tsx:419–424（项目查询错误分支也会移除整个工作区）。

复现：打开任务，修改正文但不保存；让后续任务 GET 请求返回 500，并触发窗口聚焦/重新连接等默认后台刷新。查询重试结束后 detail.isError 为 true，即使仍有缓存数据，界面也改为“任务加载失败”，TaskEditor 被卸载，其本地 draft 丢失。恢复网络并点击重试，重新挂载只剩服务器正文。整个过程没有路由离开，也不会触发 beforeunload 或 useBlocker 提示。

影响：普通读取失败即可清除本地编辑，违反保存失败保留输入及服务端缓存与编辑草稿分离的要求。现有 TaskEditor 独立单测不覆盖 App 的卸载路径。

建议：有缓存数据时维持编辑器挂载，将后台查询错误作为旁路提示；项目查询失败也应保留已有工作区。显式重新载入仅在读取成功并确认丢弃后重置草稿。

## 两个结论

1. **规格符合性：暂不通过。** 静态核对显示同项目父子、一层限制（含有子任务的根节点不得降为子任务）、父子阶段独立、五阶段校验、任务修改/移动事务内归档保护及服务端版本校验均有对应实现；但项目编辑并发与前端草稿保留仍存在上述重要缺陷。
2. **质量及阶段门槛：修复后再验收。** 未发现需列为严重级别的确定缺陷。当前不能认定阶段 1 完成；除修复以上两项外，仍需取得主线程正在执行的真实浏览器与 Docker 持久化验收结果。本文不是上述检查的通过证据。
