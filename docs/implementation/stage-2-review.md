## 重要问题

### [P2] 嵌套检查项点击同时触发祖先，最终修改错误的项目

位置：web/src/components/markdown/MarkdownPreview.tsx:29–43。

复现正文：

```markdown
- [ ] 父项
  - [ ] 子项
```

在预览点击子项复选框，事件先经过子项 span，再冒泡至包含整个子列表的父项 span。两次处理都只检查 event.target 为 INPUT，因此分别调用 onChange；它们都从同一 value 生成替换正文，父项的调用最后执行，将子项修改覆盖，最终只有父项变为已勾选。源码 offset 正确并不能防止事件命中错误祖先。现有测试仅覆盖同级重复检查项。

影响：普通嵌套任务列表会修改用户未点击的检查项，随后自动保存，违反仅修改指定检查项的要求。

建议：只由复选框所属的最近任务项处理事件，或处理后停止传播；增加嵌套父子列表回归用例，断言只回传一次且仅子项标记改变。

### [P2] 任务保存中撤回至基准正文后，路由离开不提示并丢失最新输入

位置：web/src/features/task/TaskEditor.tsx:45；相关逻辑为 web/src/app/App.tsx:30–32 和 web/src/components/markdown/useAutosave.ts:57–62。

复现：任务正文最初为 A；改为 B，等待自动保存 PATCH B 发出并延迟响应；请求在途时将正文改回 A，然后通过应用导航离开任务。此时 draft 等于旧 baseline，dirty=false，但 busy=true。TaskEditor 的 data-dirty 只使用 dirty，因此全局路由保护没有提示就卸载编辑器。PATCH B 随后成功，服务器最终保存 B；回改的 A 未能进入下一轮保存，重新打开任务看到 B。

影响：慢网络下用户最后输入可静默丢失。关闭标签页的 hook 已同时检查 busy，PageEditor 也已用 dirty || busy，任务的应用内导航保护遗漏了这一条件。

建议：TaskEditor 的导航标记也包含 busy，并增加延迟保存、改回原文、应用内离开的回归用例。

## 范围内其余核对

页面父级检查与写入同一事务执行，拒绝自身、后代及跨项目父级；祖先检查和前端树遍历使用迭代。移动会重排目标与原父级的兄弟顺序，正文/移动使用版本校验。自动保存捕获快照，限制一个请求在途；失败停止自动重试并保留草稿，409 不自动采用新版本覆盖服务器，提供复制与显式重新载入。页面后台读取失败时仍保留已有编辑器。

Markdown 跳过原始 HTML，沿用 react-markdown 默认 URL 过滤，代码围栏不渲染任务输入框；同级重复文案使用源码位置定位。附件采用限额流式写入、随机存储键及同目录原子改名，文件名拒绝路径分隔符，数据库失败清理文件；只内联允许位图，其他类型以 attachment、nosniff、CSP 返回。页面更新/移动及附件上传在事务内检查项目归档状态；未暴露删除入口。本次未发现这些路径中需要列为重要问题的其他确定缺陷。
