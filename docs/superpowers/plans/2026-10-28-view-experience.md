# View Experience Implementation Plan

**Goal:** 完成用户选定的视图记忆、日程时间轴、详情一致、排序。
**Spec:** docs/superpowers/specs/2026-10-28-view-experience-design.md
**Architecture:** 前端项目/类型偏好与纯排序模块；现有事件范围 API 驱动时间轴；通用详情组件保留各类型自己的业务保存逻辑。
**Tech Stack:** 现有 React/TypeScript/Luxon/FullCalendar，不增依赖和 schema。

- [x] 通用偏好/排序模块和单元测试；旧任务视图偏好兼容，坏数据/禁用存储测试。
- [x] 日程日历/时间轴切换、范围/缩放记忆、排序、加载/错误/空/归档、单元测试。
- [x] 详情结构共用组件、三种对象接入、笔记排序与记忆。
- [x] 根任务页设置、排序、分组与阶段折叠及记忆，父子结构/筛选/拖动回归。
- [x] 专项浏览器/视觉检查，完整单元/浏览器测试，独立审查。
- [x] Docker 构建、备份、部署/数据核对、README/验收记录、本地 Git 提交。

范围决定：本轮偏好仅当前浏览器；时间轴不支持改期拖拽，避免与现有已验证日历写入路径形成第二套不一致的业务逻辑。创建/修改日程仍连接同一真实 API。
