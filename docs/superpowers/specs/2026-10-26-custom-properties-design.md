# 同项目同类型共享自定义属性

用户已确认：新增属性的流程是添加属性→先选文本/单选/多选/网址→命名→填写当前对象的值。定义在同项目同类型的所有已有和新建对象上自动出现，值各自独立。此功能明确扩展原V1不含自定义字段的范围。

## 行为与边界

- 创建类型后立即产生默认名（文本/单选/多选/网址，同名自动加数字），随后自动打开命名设置；名称和选项编辑自动保存，当前对象的值也自动保存。
- 名称、类型、候选项属于共享定义；类型创建后固定。选项用稳定ID，支持新增和重命名，不删除候选、不转换类型、不永久删除定义，避免未经设计的数据损失。
- 单选为选项ID或null；多选为去重ID数组；文本/网址为字符串或null。空值默认显示未填写。网址仅允许完整HTTP/HTTPS地址，不执行脚本链接。
- 归档只读；已删除对象/项目不可写，恢复原删除批次后属性值仍在。自定义字段不改变固有阶段、时间、父子约束。
- 定义与值各有版本号。属性值不增加正文的版本号；删除预览指纹纳入定义及值的版本，避免并发属性修改绕过再次确认。
- 创建复用既有持久幂等请求，值和定义编辑复用既有草稿/自动保存机制；失败、冲突保留输入，显式重新载入才丢弃草稿。
- 工程默认限额：每项目每类型64定义、名称80字符、100个选项、文本4000字符、网址2048字符。候选名同范围不重复，定义名同类型不与固有属性混淆。

## 持久化与API

schema9仅新增两表：custom_property_definitions与custom_property_values；定义含options JSON，值含value JSON与独立version。复合外键绑定定义的项目/类型，以及对应task/page/event原生对象，禁止跨项目/类型关联。原有正文/对象行不回填、不重写。

- GET/POST /api/v1/projects/{id}/property-definitions/{type}
- PATCH /api/v1/property-definitions/{id}，version/name/options
- GET /api/v1/objects/{type}/{id}/custom-properties，返回fields和read_only
- PUT /api/v1/objects/{type}/{id}/custom-properties/{propertyId}，version/definition_version/value
- 通用对象视图也返回custom_properties；普通构造函数装配独立customproperty模块，不引入通用属性引擎或新依赖。

属性栏保持现有紧凑样式，自定义字段排在固有属性后，末尾“添加属性”；名称可点开设置。此次采用共享定义+稀疏值，未采用逐对象复制定义（不能自动共用）或全项目跨类型定义（用户已排除）。
