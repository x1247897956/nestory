# 个人笔记与任务软件：第一版产品设计

日期：2026-10-23

本文整理已确认需求，并为未单独讨论的细节给出明确的建议默认值。页面布局与默认值仍可在开发规划前调整。

## 1. 定位与范围

面向单人使用，以项目聚合思考、执行与时间安排。Docker 自部署，第一版提供 Web 前端，仅用于本机或局域网，不提供登录、注册、团队权限与协作功能。

每个项目包含一个任务列表、一棵笔记页面树和一组日程。Task、Page、Event 均且仅属于一个项目。全局工作台汇总内容，不改变归属。

第一版不包含自定义字段配置、自定义阶段配置、看板视图、重复日程、提醒、跨项目关联、任务依赖与自动化流转。

## 2. 信息结构与导航

建议采用左侧项目导航、右侧内容区。全局入口为今日工作台、搜索、归档项目、回收站。选中项目后展示任务、笔记、日历三个入口；笔记入口支持展开子页面树。

项目内只有一个任务列表；按阶段分组或筛选不会产生新的列表实体。

### 今日工作台

- 今日到期任务：截止日期为今天且尚未 Done / Cancelled 的任务与子任务。
- 逾期任务：截止日期早于今天且尚未 Done / Cancelled 的任务与子任务。
- 今日日程：时间区间与今天相交的 Event，包含跨日事件。
- 最近访问：最近打开的项目和 Page。
- 归档项目的内容默认不参与以上汇总。

以上内容显示所属项目；子任务同时显示父任务，点击进入对应对象。建议所有“今天”判断统一使用部署配置的时区，默认 Asia/Shanghai。

### 项目页

项目头部显示名称、说明与归档操作，下方切换任务、笔记、日历。

- 任务：列表展示，默认按阶段分组；展开父任务查看一层子任务。
- 笔记：页面树加编辑区，正文提供源码、预览、分屏模式。
- 日历：建议默认周视图，支持切换月视图和定位今天；点击日期或时间段创建日程。

全局搜索建议覆盖未删除对象的标题与正文，显示类型、所属项目和 Page 路径；归档内容可显式纳入搜索。

## 3. 对象与固定字段

所有对象使用稳定 ID，记录创建、更新时间和软删除时间，链接不依赖标题或页面路径。

| 对象 | 第一版字段 |
| --- | --- |
| Project | 名称、说明、归档时间 |
| Task | 标题、Markdown 描述、阶段、优先级、截止日期、父任务、同级顺序、关联 Page、关联 Event |
| Page | 标题、Markdown 正文、父页面、同级顺序、关联 Task、关联 Event |
| Event | 标题、Markdown 描述、开始时间、结束时间、关联 Task、关联 Page |

标题必填。描述与正文可空。优先级建议固定为未设置、低、中、高，默认未设置；截止日期可空，第一版按日期管理。Event 的起止时间必填，结束时间必须晚于开始时间，允许跨日和时间重叠，第一版不增加全天事件类型。

## 4. Task 与子任务

阶段固定为 Todo、InPlan、InProcess、Done、Cancelled，表示看板式工作流中的位置。默认顺序为 Todo → InPlan → InProcess → Done，Cancelled 为另一结束阶段；该顺序不是强制流转限制。

- 新建任务默认 Todo，允许任意阶段之间切换。
- Done 与 Cancelled 不进入未完成任务汇总。
- 子任务拥有与主任务相同的业务字段和关联能力，只能有一层，父子必须同项目。
- 父子阶段独立；全部子任务完成不会自动完成父任务，完成父任务也不会修改子任务。
- 即使父任务已经完成，未完成的子任务仍按自身日期进入全局工作台。
- 检查清单存于 Markdown 的 `- [ ]` / `- [x]` 中，预览中的勾选操作写回正文，不自动修改任务阶段。
- 检查清单项没有独立阶段、日期或关联字段。

建议删除父任务时，其子任务一并进入回收站，并明确提示范围。

## 5. Page 与 Markdown 编辑

Page 支持嵌套子页面，第一版不设置产品层级上限。父子必须同项目，禁止将页面移动到自身或后代下面。

Task、Page、Event 复用 Markdown 编辑能力：源码、预览、分屏，支持常用 Markdown、代码围栏与语法高亮、图片及附件链接。预览不执行嵌入的脚本。

图片与附件上传到本地持久化存储，插入稳定资源地址的 Markdown。图片可预览，普通附件可下载。建议第一版通过上传按钮选择文件，不把富文本编辑、复杂附件预览和图片处理纳入必需范围。

建议正文采用短暂防抖自动保存，并显示保存中、已保存、保存失败；失败时保留当前输入并提供重试，页面离开时对未保存内容提示。第一版不要求离线编辑和历史版本管理。

子页面只是层级归属，不自动继承父页面的字段关联。

## 6. Event

Event 是独立的时间安排，不是 Task 的时间字段或任务执行记录。创建 Event 不要求关联任务。关联后的阶段、时间、标题均不会自动同步。

日历卡片展示标题和起止时间，打开后编辑正文、时间与关联。跨日事件按实际区间展示。数据库建议保存标准化时间，显示和输入统一转换到部署时区。

## 7. 项目内双向关联

第一版支持三组多对多关联：Task ↔ Page、Task ↔ Event、Page ↔ Event。

- 在任一端添加或移除，另一端同步反映同一关系，不能维护两份独立值。
- 选择器仅展示同项目、未删除的目标，可搜索标题；Page 显示路径，Task 显示阶段，Event 显示时间。
- 同一对对象不可重复关联。服务端必须校验双方项目一致。
- 不支持 Task ↔ Task、Event ↔ Event 的通用关联；Page ↔ Page 的第一版结构关系为父子关系。
- 正文普通网址不自动产生关联字段或反向链接；跨项目页面网址仅作为普通链接处理。
- 第一版不提供跨项目移动对象，避免隐式破坏父子关系与关联。

示例：在“设计讨论”Event 中关联“登录方案”Page，Page 的关联日程立即出现该 Event。再将“实现登录”Task 关联到这两个对象，三者各自独立编辑。

## 8. 归档、删除与恢复

归档项目保留全部内容和关系，项目内容只读，可查看、搜索和取消归档。它从默认项目导航、今日工作台与默认日历汇总中隐藏，归档列表提供入口。

第一版建议不提供整个项目的删除入口，先支持归档。

删除 Task、Page、Event 使用回收站。删除 Page 时整棵子树一起删除；删除父 Task 时子任务一起删除。删除操作显示影响数量。

软删除对象的关系记录仍保留，未删除一端显示“已删除”的占位关联。恢复后原关系重新可用。按一次删除操作记录受影响对象，恢复时只恢复该次删除的后代，不误恢复先前已删除的内容。

若所属父对象仍在回收站，恢复子对象时应提示先恢复父对象或一起恢复，不静默改变层级。归档项目中的删除对象，需要先取消归档再恢复。

第一版回收站不自动清理，不提供永久删除；附件随数据库备份保留，暂不自动回收文件。

## 9. 关键操作流程

1. 创建项目 → 添加 Page 梳理方案 → 添加任务 → 通过关联字段连接方案。
2. 创建父任务 → 添加一层子任务 → 描述中记录检查清单 → 分别推进阶段。
3. 在项目日历选择时间 → 创建 Event → 按需关联 Page 与 Task。
4. 从今日工作台打开逾期或今日任务 → 更新阶段 → 汇总随之更新。
5. 项目结束 → 归档 → 从活跃工作视野移除 → 必要时取消归档继续编辑。

## 10. 开发边界与扩展原则

公共元数据、各对象专属字段、关联关系分开组织。固定字段保持明确类型与校验，第一版不实现动态字段引擎。

阶段应使用稳定标识与显示名称分离的设计，将阶段顺序和“完成／取消”语义集中定义，避免业务代码依赖显示文字。后续按项目开放自定义阶段时，可沿用 Task 数据。

未来自定义字段可增加字段定义和对象字段值，而无需把当前固定字段全部转换为任意 JSON。关联规则集中校验，为后续调整范围提供清晰入口，但第一版始终限制同项目。

Docker 持久化覆盖数据库和附件，容器重建不能丢数据。提供配置示例、启动说明和数据库与附件的一致性备份／恢复步骤。免登录意味着部署范围限定在本机或受信任局域网。

具体前后端框架、数据库、Markdown 编辑器与日历组件在实施规划中选择，本产品文档不提前锁定。

## 11. 第一版验收标准

- 重启或重建容器后，项目、正文、任务、日程及附件仍存在。
- 项目内可创建唯一任务列表、一层子任务、多层 Page 与有效时间区间的 Event。
- 三类对象可编辑 Markdown，图片可显示、附件可下载、代码块可预览。
- 五个阶段能自由切换；子任务独立流转，检查项修改不隐式完成任务。
- 三组关联在任一端修改后，另一端一致更新，重复或跨项目关联被拒绝。
- Page 层级无法产生循环，子任务不能超过一层。
- 今日工作台正确区分今日与逾期任务，展示跨越今天的日程，隐藏归档内容。
- 归档项目只读且可恢复；删除与恢复保留关系和层级，不误恢复先前删除对象。
- 保存或上传失败时有可见错误，正文输入不会被静默丢弃。
- 按说明执行备份并恢复到干净环境后，正文、关联与附件仍可用。
